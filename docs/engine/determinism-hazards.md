# Known determinism hazards

Status: tracked list for [#27](https://github.com/danielsegan/sfc2.js/issues/27). Owner: Audio & Netcode QA Lead. Co-owner: Engine Lead.

This is the single list. The policy itself stays in [determinism.md](determinism.md). [ADR 0001](../adr/0001-fixed-timestep-sim-core.md) says why that policy is lockstep-safe and points here.

**Status.** `mitigated` means a guard fails CI if the covered form of the hazard comes back. `open` means no such guard runs yet. A mitigated row can still name a gap.

| Id | Hazard | Status | Guard | Gap |
| --- | --- | --- | --- | --- |
| object-iteration | Object, `Map`, and `Set` iteration order changing results or the state hash | mitigated | `eslint.config.js` bans `Object.keys` / `values` / `entries` on `engine/core` and `engine/sim`. `tools/check-sim-syntax.mjs` also flags `for-in` and those three calls; `tools/lint-fixtures/sim-violations.ts` must trip each id. Live entities are walked by ascending index in `World.liveIds` (`engine/sim/world.ts`). `Sim.canonicalBytes` (`engine/sim/sim.ts`) hashes that order, and `engine/sim/sim.test.ts` pins the hash to those bytes. | `for-of` on a `Map` or `Set` is not a lint selector. There is no test that builds two worlds through different insertion paths and compares hashes, beyond the command-order case below. |
| sort-ties | Sort stability, or a comparator that ties, changing which entity or command wins | mitigated | `tools/check-sim-syntax.mjs` rejects `.sort()` with no comparator (`sort`), proved by `tools/lint-fixtures/sim-violations.ts`. Commands sort by `(tick, slot, seq)` in `compareCommands` (`engine/core/codec.ts`). `engine/sim/sim.test.ts` shows a reversed command pair hashes the same, and that systems in one phase run by priority then system id. | The ESLint config does not include the sort ban; only the custom scanner does. A comparator that returns 0 for two different entities is not linted. |
| float-leak | A float, a transcendental, or a raw division leaking into sim state | mitigated | `eslint.config.js` bans the `Math` transcendentals, `**`, and raw `/` on `engine/core` and `engine/sim`. `tools/check-sim-syntax.mjs` also bans non-integer numeric literals, `Float32Array` / `Float64Array`, `parseFloat`, and `Math.sqrt` / `pow` / `hypot` / `fround`. Golden vectors: `engine/core/fx.test.ts` (N1a dist², cross, dot, and the BigInt floor reference). | `Math.round`, `Math.floor`, and `Math.abs` are not in the ban list. ESLint does not ban non-integer literals; the custom scanner does. |
| wall-clock | `Date`, `performance.now`, or a timer read inside the sim | mitigated | `eslint.config.js` `no-restricted-globals` bans `Date`, `performance`, `setTimeout`, `setInterval`, `requestAnimationFrame`, `Promise`, and `queueMicrotask`. `tools/check-sim-syntax.mjs` flags those plus `async` / `await`. The driver is the only clock: `engine/driver/fixed-step.ts`. `engine/driver/fixed-step.test.ts` checks that 1×, 2×, and 4× produce the same hash sequence. | The lint glob is `engine/core` and `engine/sim` only. The driver consumes a host-supplied frame delta; that read stays outside the sim on purpose. |
| unseeded-rng | `Math.random` or any draw that is not a named seeded stream | mitigated | `Math.random` is banned by both `eslint.config.js` and `tools/check-sim-syntax.mjs`. Golden vectors and the zero-state remap: `engine/core/rng.test.ts`. Stream words are restored in `STREAM_NAMES` order (`ai`, `combat`, `mission`) and are part of `canonicalBytes`. An unregistered `fork` throws; `engine/core/rng.test.ts` covers that. | Nothing statically checks that a call site draws from a registered stream. The check is the runtime throw. |
| json-key-order | `JSON.stringify` key order, or any object-key order, feeding the state hash or `versionHash` | mitigated | The state hash is `xxHash32` over `canonicalBytes`: tick, RNG words in name order, then world tables in registry order as little-endian int32 (`engine/sim/sim.ts`, `engine/core/bytes.ts`). It does not stringify objects. `simSourceHash` sorts paths before hashing (`engine/core/version.ts`, `engine/replay/sources.ts`). `engine/core/version.test.ts` and `engine/core/xxhash32.test.ts` pin the mix. | `JSON.stringify` is not banned in sim packages. A new hash that stringified an object would not be caught by lint. |
| locale | `Intl` or `localeCompare` / `toLocale*` changing order or parsing | mitigated | `eslint.config.js` bans the `Intl` global. `tools/check-sim-syntax.mjs` flags `localeCompare`, `toLocaleString`, `toLocaleLowerCase`, `toLocaleUpperCase`, `toLocaleDateString`, and `toLocaleTimeString`. Both fire on `tools/lint-fixtures/sim-violations.ts`. | `globalThis['Intl']` would not match the identifier check. |
| worker-main | Worker and main thread diverging on the same commands | mitigated | `tests/worker.test.ts` runs `tests/sim-worker.ts` and compares per-tick state and event hashes with the main thread for a seeded `createSim` stepped with empty commands. `engine/sim/sim.test.ts` restores a snapshot through structured clone and continues the same hash sequence. | The worker test does not load combat, heading, or the replay corpus. Worker transport (structured clone versus shared memory) is still open in determinism.md §10. |
| wasm-i64 | WASM i64 and the TypeScript hi/lo split disagreeing on dist², cross, or dot | open | The TypeScript path is pinned by the N1a golden vectors in `engine/core/fx.test.ts`, checked against BigInt in tests only. The required approach is determinism.md N1a and sim-core.md N1a: exact i64, no float, native i64 on the WASM side, `Math.imul` split on the TypeScript side. | No WASM sim source is in the tree, so the H5 gate (WASM and TypeScript hashes match on the replay corpus) does not run. |
| typed-array-endian | A typed-array or `DataView` read using host endianness in the hash or the command codec | mitigated | `engine/core/bytes.ts` writes and reads with explicit shifts (little-endian), not a host-endian `DataView`. The state hash and the command codec both use those helpers. `engine/core/codec.test.ts` round-trips a little-endian envelope and checks payload bytes. | CI is little-endian only. There is no big-endian host job. The shifts do not consult host endianness. |
| input-delay | Stamping a command from the wall clock or from arrival time instead of the sim tick | mitigated | `LocalSession.issue` (`engine/net/session.ts`) stamps `current + 1` when delay is 0, and `current + delay` for delay 2, 3, or 4. Delay 1 is rejected. `engine/core/codec.test.ts` checks that delay 3 from tick 10 stamps tick 13, and that `seq` restarts at 0 each tick. ADR 0001 records the same rule. | There is no multi-peer loss or latency simulator. The C6 check (a bundle for every slot, sim waits until it is present) is not implemented; only the single-player stamp is. |

When a row's gap closes, update the status in this table in the same PR as the guard. Do not drop a row because it is mitigated.
