# Replay file and CI hash check

Status: accepted for [#25](https://github.com/danielsegan/sfc2.js/issues/25). Normative rules stay in [determinism.md](determinism.md) (C4, C8, H3, H6, V1, V2). This file is the envelope those rules did not spell out byte for byte.

The corpus under `replays/` is synthetic. It is scripted ships with made-up positions. It is not a recording from a Starfleet Command 2 install, and it contains no game assets.

## What a file is

Little-endian. Magic `SFC2RPLY` (8 bytes), then:

| Field | Type | Notes |
| --- | --- | --- |
| replayFormat | u32 | `REPLAY_FORMAT` in `engine/core/version.ts`. This build plays 1. |
| simSourceHash | u32 | xxHash32 of sim sources. See below. |
| dataHash | u32 | Game database hash. The corpus uses the empty database, so this is 0. |
| versionHash | u32 | `versionHash(replayFormat, simSourceHash, dataHash)` from determinism.md V1. |
| scenarioHash | u32 | Same path recipe as `simSourceHash`, over the scenario's own source files. Not mixed into `versionHash`. |
| matchSeed | u32 | Seed passed to `createSim`. |
| tickCount | u32 | Number of `step` calls. At least 1. |
| scenarioId | u16 length + ASCII | Lowercase token such as `scripted-duel`. |
| settings | u32 length + bytes | Exactly 4 bytes: `u8 version=1`, `u8 inputDelay`, `u16 hashPeriod`. |
| slots | u8 count + u8[] | Player slots 0–5, strictly increasing. |
| snapshot | u32 length + body | Tick-0 `Snapshot` (RNG streams, world, queued commands). |
| commands | u32 length + bundle | Player log only, already in `(tick, slot, seq)` order. The bundle is the existing command codec (`u32 count`, then each `encodeCommand`). |
| hashes | u32 count, then records | Each record is `u32 tick`, `u32 stateHash`, `u32 eventHash`. |

`hashPeriod` 1 stores a sample at every tick from 0 through `tickCount`. A larger period stores tick 0, every tick divisible by the period, and the final tick. The corpus uses period 1, so the first mismatched sample is the first divergent tick.

`inputDelay` is recorded (0, or 2–4) and is not applied again on playback. The script already stamps each command with the tick it applies in.

AI slots 8–15 and mission slot 255 must not appear in the command log. Those commands are regenerated by the scenario (determinism.md C4). The tick-0 snapshot may still contain a queued internal command; that is sim state, not the player log.

Playback restores the snapshot, checks it matches a fresh `createSim` for the seed, then steps. A version mismatch refuses to step.

## Version stamp

`simSourceHash` is xxHash32 over `engine/core/**/*.ts` and `engine/sim/**/*.ts`, tests excluded, in sorted repo-relative POSIX paths. Each file is `utf8(path) ‖ 0x00 ‖ fileBytes`, which is the function already in `engine/core/version.ts`. Docs, `engine/driver`, `engine/net`, `engine/replay`, and tests are not included, so a doc-only commit does not invalidate a replay.

`scenarioHash` covers the scenario sources listed on that scenario (the synthetic script and, when it uses them, `engine/replay/scenarios/kit.ts`). V1's `versionHash` formula is only format + sim sources + data, so a script edit must not be folded into that formula. The separate stamp makes a script edit fail as a stale replay instead of a tick divergence that looks like a sim bug.

`.gitattributes` forces LF on text and marks `*.s2replay` binary so the source hash does not depend on `core.autocrlf`.

Re-baselining a corpus file is a determinism change: say why in the PR. `pnpm replay:record` rewrites `replays/` from the scripts.

## Runner

```
pnpm replay:check
pnpm replay:record
pnpm replay:browsers
```

`replay:check` is the CI gate. It exits non-zero on a stale stamp or a hash mismatch. A mismatch prints `first divergent tick: N` plus the expected and actual state and event hashes, the scenario id, and the seed. A stale file prints `STALE` and names the part that differs (`replayFormat`, `simSourceHash`, `dataHash`, `versionHash`, `scenarioHash`) and does not step.

The browser job loads the same files in Chromium, Firefox, and WebKit and compares each hash timeline to a Node playback. The page cannot read the source tree, so it does not recompute `simSourceHash`. The Node corpus job is what refuses a stale stamp. The browser job is what proves the hash timeline matches Node.
