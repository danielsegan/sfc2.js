# Tactical HUD Interaction Audit (SFC2 CE 2.670 vs `main`)

Status: draft v0.1 (2026-11-25, SUAD-2 Phase 1). Owner: UI & Art Director.
Baseline branch: `main` (`5e70581`). Reference baseline: *Starfleet Command II: Empires at War — Community Edition* (CE) 2.670.

Purpose: Daniel's direction (2026-11-25) keeps our modern visual style (`docs/ui/style-guide.md`, `docs/ui/hud-layout.md`) while bringing controls, feedback, and HUD behaviour closely in line with the original SFC2. This audit compares each interaction area against `main`, cites exact files and functions, rates every gap (`High` / `Med` / `Low`), and ends with a ranked PR plan ordered **smallest first** within priority.

**Sources & verification marks:**

- **M2**: *Starfleet Command II* Gameplay Manual & Reference Guide (TrekCore mirror, `sfc2.pdf`).
- **G1 / G2 / XP**: Public community guides (GameFAQs `faqs/10875`, `faqs/17237`, TrekCore `faq.html` / `walkthrough.txt`, XenoCorp `power_management.htm`).
- **Docs**: `docs/ui/hud-layout.md`, `docs/ui/hud-spec.md`, `docs/ui/keymap.md`, `docs/ui/modern-ux.md`, `docs/rules/`.
- **TO VERIFY**: Any original behaviour, step size, button layout, or keybinding not yet confirmed against Wintermute's CE 2.670 reference notes (`/workspace/sfc2-screens/ce-ref/`, not yet present at audit time). Every **TO VERIFY** entry is an explicit slot to check once those notes land.
- **Boundary rule**: The HUD reads `ViewModel` (`engine/view/view-model.ts`) and dispatches `Command` / `DuelMatch` calls (`engine/duel/match.ts`) only. Where closing a gap needs a new sim verb or `ViewModel` field, that dependency is flagged so Engine / Combat can wire it cleanly without HUD-side sim writes.

## Summary of Gaps by Area

| Area | Highest Gap | Key Gaps |
| --- | --- | --- |
| 1. Power / energy allocation | **High** | No 1–5 priority sliders (Movement / Weapons / Shields / Tractors / ECM), no live Excess or Battery toggle, `#field-cap` sets raw energy instead of `%` recharge marker, `#field-power` systems bar uses weapon costs as a stand-in. |
| 2. Shield reinforcement | **High** | Click immediately increments `+1` per arc (no select-arcs → slider → `Reinforce` / `Reinforce All` commit flow, no centre-ship toggle all/none, no Down/Minimal/Up shield-state control). |
| 3. Weapon arming, firing & groups | **High** | `1–6` selects a group instead of SFC2 `1–4` select + `R` select-all; no `Shift+click` multi-select on schematic hardpoints; no `Alpha Strike`; no hold-charge / underload / point-defense toggles. |
| 4. Helm & speed | **High** | `#field-speed-bar` supports click/wheel only (no drag); 7 of 9 `#helm-grid` HET buttons + `Go` stay disabled; no HET success `%` readout; no `EmerDecel`, `Erratic`, or `Intercept`/`Orbit` controls. |
| 5. Targeting & target info | **High** | No docked Target Schematic panel with target weapon hardpoints/charge at scan-gated detail; floating `.target` panel is text-only with no target shield ring. |
| 6. Damage & system displays | **High** | No Damage Control / Repair officer page (internal system boxes, crew/marines, repair priority queue); systems row is splayed across 5 plates instead of a 6-button System MFD beside the Ship Schematic. |
| 7. Map & zoom | **High** | Sensor map is permanently pinned in top-right `#overlay` instead of being one Officer MFD page (`hud-layout.md` D2); lacks +/- zoom buttons and race-coloured glyphs. |
| 8. Hotkeys | **Med** | Modern default keymap works and rebinds, but has no "SFC2 Classic" preset, no bindings for HET port/starboard, no Officer MFD page hotkeys, and no interface-bar toggle. |
